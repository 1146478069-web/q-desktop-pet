# 2.5D Pet Actions Design

## Goal

Add a richer action system and a lightweight 2.5D visual treatment while keeping the uploaded image as the pet's actual body.

## Selected Direction

Use a CSS 3D "paper character" model instead of a full WebGL model for this phase.

The uploaded avatar remains the main character image. The renderer wraps it in a 2.5D stage with perspective, a subtle side-depth layer, ground shadow, tilt, and motion states. This gives a clear 3D feeling without adding a heavy graphics dependency or risking transparent-window compatibility.

## Pet Actions

Add named pet moods/actions that can be applied by interaction logic:

- Idle: breathing, floating, and a slow left/right turn.
- Happy: jump, squash/stretch, and small sparkle accents.
- Reward: softer forward lean and cheerful bounce after long left press.
- Annoyed: shake, turn-away motion, and irritated bubble after repeated pokes.
- Angry: stronger turn-away and sharper shake after heavy repeated pokes.
- Sleepy: lowered pose, slow breathing, and small sleep marks when idle for a while.
- Carried: lifted pose while left and right mouse buttons are held for move mode.

The current poke/reward/move behavior stays intact. The action system changes how the pet looks while those behaviors run.

## Settings

Extend `AppSettings` with:

- `visualMode`: `"classic"` or `"paper3d"`, default `"paper3d"`.
- `motionIntensity`: `"soft"` or `"lively"`, default `"lively"`.

The settings window gains controls for these fields:

- A 2.5D effect toggle that maps to `visualMode`.
- A motion intensity control with Soft and Lively options.

If 2.5D is off, the pet uses the existing flat image layout and simpler animations.

## Renderer Design

The standalone renderer remains the runtime source of truth.

For the pet view:

- Add a stage container with `perspective`.
- Add a body wrapper that owns 3D transforms.
- Render the avatar image as the front plane.
- Add a subtle depth plane behind the avatar.
- Add a ground shadow under the pet.
- Add optional accent marks for happy and sleepy states.
- Apply action classes such as `pet-action--idle`, `pet-action--happy`, and `pet-action--carried`.

The React renderer files may be kept in sync for typechecking, but packaged runtime behavior is driven by `scripts/build-standalone-renderer.cjs`.

## Action Flow

- On app start, the pet starts in Idle.
- Short left click runs Poke, then escalates to Annoyed or Angry based on the existing poke counter.
- Long left press runs Reward and clears the poke counter.
- Holding left and right buttons runs Carried while the window moves.
- If there is no interaction for a longer idle period, the pet can enter Sleepy.
- Any direct interaction wakes the pet from Sleepy.

Actions are temporary except Idle and Sleepy. A timed action returns to Idle unless a newer action has already started.

## Error Handling

Unknown or missing settings fall back through `mergeSettings`.

If CSS 3D support behaves poorly on a system, the user can disable the 2.5D effect in settings and continue using the classic flat pet.

Uploaded images still use the existing local avatar processing pipeline. This feature does not change file import rules.

## Tests And Verification

Automated coverage:

- Validate default and merged settings for `visualMode` and `motionIntensity`.
- Confirm unsupported setting values fall back to defaults.
- Keep existing audio, avatar, cutout, and settings tests passing.

Manual verification:

- Build succeeds.
- Packaged app opens.
- Uploaded avatar appears as the 2.5D pet body.
- Toggle between 2.5D and classic modes works from settings.
- Soft and Lively intensity visibly differ.
- Short click, repeated click, long press, and left+right move all trigger the expected action classes and visual responses.
